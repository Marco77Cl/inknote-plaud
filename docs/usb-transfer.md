# USB 数据线直连（v0.4.1）

2026-10-23。

## 操作

1. 使用支持数据传输的 USB 线连接设备与 Mac。
2. 设备主菜单 → 阅读 → **USB 数据线传输**。保持此页面。
3. InkNote Studio 中点击 **刷新 USB**，自动选择设备（多台时手动选择），点击 **USB 连接**。无需 Wi-Fi 和六位配对码。
4. 下载录音：设备录音 → 下载/下载全部新录音。
5. 导入书籍：阅读 · 书籍与笔记 → 导入 EPUB/TXT → 选中书籍 → 同步所选到设备。
6. 传输结束后，设备双击 BOOT/拨轮返回，再打开书架或录音功能。

本版本通过 InkNote Studio 传输，设备不会作为 Finder U 盘挂载。避免计算机与设备同时直接挂载 TF 文件系统。录音原件保留，USB 下载与书籍同步均校验 SHA-256。

## 失败处理

- 没有设备：检查数据线而非仅充电线，点击刷新 USB。
- 无法打开串口：关闭串口监视器或烧写工具；同一 USB 串口不能同时被它们和 Studio 占用。
- USB 未响应：设备需停留在 USB 数据线传输页，重新连接。若插拔后设备重启，重新进入该页。
- 退出页面或拔线导致传输中断：原录音保留；书籍未完整校验时不会出现在书架。重新进入后重试。
- USB 下载暂不续传；重试会重新下载该录音。Wi-Fi 下载原有续传逻辑保留。

## Wi-Fi 修复

旧同步页仅接受已初始化的 STA 驱动。设备关闭 Wi-Fi 后会停止或反初始化驱动，进入同步即失败。新版同步页在需要时创建临时热点，退出恢复关闭状态，不改变保存的家庭 Wi-Fi 开关与凭据。阅读菜单入口改为「Wi-Fi 同步内容」，Mac 提示同步更新。

## 实现与验证

- 使用 ESP32-S3 现有 USB Serial/JTAG 接口，显式 USB 传输页内运行串口传输任务。
- USB 帧带随机请求标识、Base64 分块。通过芯片内 loopback 访问同一个文件 API，沿用配对 token、路径检查、SHA-256、临时文件与提交规则，不新增任意路径读写功能。
- USB 页面不启动无线热点；USB 物理连接获取本次临时会话 token。
- 固件和 Mac 应用编译通过。Mac 已重启显示 USB 连接入口。
- `tests/check_usb_transport.py` 使用真实 Swift 客户端和系统伪终端，覆盖准确上传字节、日志混杂、分块/定长响应、等待、截断与长度不符拒绝，4 个场景通过。
- 日志：`logs/usb-build.log`、`logs/usb-mac-build.log`、`logs/usb-transport-native-tests.log`、`logs/usb-flash.log`。
- 已完成实机 USB 验证：读取 32 段录音列表，下载 `rec_0523ff82.wav`（15.04 秒，481324 字节），设备 SHA-256 与 Mac 文件及校验记录一致，WAV 结构为单声道 PCM16 / 16 kHz；两章中文示例书上传成功，原生 UI 显示同步与 SHA-256 校验通过。
- 实机发现 HTTP 接口保持连接，Mac 完成判断已改成 Content-Length/最终分块，不依赖服务端关闭 socket；伪终端测试加入连接不关闭的场景。
- 固件已刷写并通过哈希校验。汇总：`logs/usb-validation.json`。尚待：实体书籍阅读排版、目录/书签/续读、大文件/拔线恢复，以及 Wi-Fi 修复后的热点实测。
